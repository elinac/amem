# amem 设计文档审核协议

目标：通常在 **2 轮**内关闭阻塞项；高风险设计最多 3 轮。避免逐条修补产生新抽象，再由下一轮发现二阶缺口。

## 1. 审核前置条件

未满足以下条件，不开始多人审核：

1. **基线固定**：记录文档版本、Git commit、相关依赖版本和官方 API commit/tag。
2. **范围固定**：列出目标、非目标、P0/P1、条件性交付和明确延期项。
3. **不变量矩阵**：至少覆盖真相源、权限、原子性、失败模式、兼容性和数据边界。
4. **接口清单**：列出新增/修改的类型、API、状态机、持久化文件和宿主接缝。
5. **证据包**：给审核者相同的工程文件、官方文档和已接受决策；不让每个审核者自行猜基线。

缺少公开官方 API 时，先由一名框架研究者给出结论，再进入架构审核。

## 2. Finding 分级

只有以下情况可标为 `BLOCKER`：

- 方案无法在当前工程或固定依赖版本上实现；
- 违反已声明的不变量或安全边界；
- API、状态机、真相源或交付范围自相矛盾；
- 正常并发、崩溃、迁移会造成不可恢复的数据损坏；
- 验收标准无法判定或关键用户流程无法完成。

以下不得升级为 blocker：

- 更优雅但非必要的重构；
- 尚无数据证明的未来扩展；
- 文案、命名、样式偏好；
- 已明确延期且不破坏 P0 的能力；
- 与既有 accepted 决策冲突、但没有新工程证据的重新讨论。

每个 finding 必须包含：证据位置、具体失败场景、受影响不变量、最小修复。缺一项则降为可选建议。

## 3. 两轮默认流程

### Round 1：一次性广审

并行启用适用角色，一次覆盖：

- 一致性与术语；
- 工程可行性和官方 API；
- 数据、并发、崩溃与迁移；
- 安全、权限与隐私；
- 产品范围和条件性交付；
- UI 流程、错误态、响应式与可访问性。

主审人随后：

1. 去重 findings；
2. 按共同根因聚类，而不是按审核者逐条修；
3. 产出“阻塞项关闭矩阵”：根因 → 受影响章节/接口/测试 → 修复；
4. 一次性完成修复和横向影响分析。

横向影响分析必须检查：

- 新类型是否需要 schema、序列化、迁移与测试；
- 新状态是否需要创建、读取、恢复、撤销和并发语义；
- 新写路径是否经过统一权限、事务和审计；
- 新宿主 API 是否固定版本并有降级；
- 新 UI 操作是否有 API、权限、加载/错误/成功和无障碍闭环。

### Round 2：差异关闭审核

不重新开放整份方案。审核输入固定为：

- Round 1 关闭矩阵；
- 修复后的文档 diff；
- 新增或改变的不变量、接口和状态机。

审核者只允许：

1. 验证原 blocker 是否关闭；
2. 报告由本次修复**直接引入**的新 blocker；
3. 报告 Round 1 已有证据包中被遗漏、且会破坏不变量的 blocker。

不接收新的可选优化、未来扩展或偏好争议。无 blocker 即退出。

## 4. 第三轮与轮次上限

只有 Round 2 仍有 blocker 时进行 Round 3，并只邀请与剩余根因相关的角色。Round 3 是定向终审，不再全角色广审。

- 默认上限：2 轮；
- 高风险（认证、跨文件事务、数据迁移、外部宿主 API）：3 轮；
- 超过 3 轮必须暂停，重新拆分范围或回退过度设计，不能继续堆补丁；
- “修复已知 blocker 后的关闭验证”不算新发现轮，但只能验证该修复，不得扩展审阅范围。

最后一轮发现 blocker 时，不得出现“修完但未复审”。应执行定向关闭验证；如果仍失败，方案状态标记为 `BLOCKED`，交给用户决定拆分或降级。

## 5. 审核退出条件

同时满足才可标记通过：

- 所有 blocker 在关闭矩阵中有明确处置；
- 不变量、接口、状态机、持久化与验收相互一致；
- 官方 API 结论固定到版本/commit；
- 条件性交付有明确发布门和门前行为；
- 最后一批修复已完成定向关闭验证；
- 可选项单列，不混入 P0 实施计划。

结论只使用：

- `PASS`：无 blocker；
- `PASS_WITH_OPTIONAL`：无 blocker，有可选项；
- `NEEDS_FIX`：存在可在当前范围内关闭的 blocker；
- `BLOCKED`：需用户改范围、依赖或架构决策。

## 6. 本次五轮的教训

此前审核轮次过多，根因不是“审核越多越好”，而是：

- 首轮没有先固定 DSH 官方鉴权能力，导致后续反复修改发布边界；
- 对 finding 逐条修复，journal、authority、generation 等新抽象缺少一次性状态机审查；
- 每轮全角色重新开放审阅，范围不断扩散；
- 轮次上限按“发现轮”计算，却没有保证最后修复经过关闭验证。

今后先固定证据与不变量，再做一次广审、一次差异关闭审核；复杂方案最多增加一次定向终审。
