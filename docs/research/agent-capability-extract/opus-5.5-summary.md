# Opus 5.5 方案要点（2026-09-25）

来源：子代理 28d9d1d9-d93a-475a-9673-3c9b3d2180e9

## 核心立场

1. 业务能力当软件资产管，不当记忆管；Git Markdown/YAML 为唯一真相源。
2. 自动化只提议和刹车：可让能力变少/变弱/变待审，不能变多/变强/变宽松。
3. 约束是代码不是 prompt：OPA/Rego + 工具前置钩子强制执行。
4. 装配先确定性路由（流程/节点），再作用域内语义检索；L0/L1/L2 渐进披露。
5. 开源借思路不当地基；治理层自建且保持薄（Git + CI + OPA + 注册表）。

## 相对 GPT 的差异化

- 五类能力各有信任级别与自动演化权限（约束极低、经验高但默认低信任）
- 「只能收紧不能放宽」作为硬不变量
- 结果标签必须来自外部业务信号，禁止 LLM 自评
- 更强调装配 manifest / 因果增益评估
- EverOS 作为经验层首选起点；OpenViking AGPL 需法务评估
- 下周 12 项任务带负责人角色（E1/E2/E3/SME）
